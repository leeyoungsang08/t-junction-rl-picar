# 축소 T자 트랙 제작과 검증

[치수 도면](track-layout.svg) · [하드웨어 측정표](../config/hardware_inventory.template.yaml) · [현장 합격 기록표](../records/field_checks.csv)

## 테이프 배치 초안

차체 약 22 × 17cm를 가정한 시작 치수다. 바닥 6.0 × 4.0m에서 북서 모서리를 (0,0), 동쪽과 남쪽을 양의 축으로 잡는다. 교차로 중심 J는 (3.0, 1.1)m, W/E/S 끝은 각각 (0.4, 1.1), (5.6, 1.1), (3.0, 3.6)m다. 갈래마다 진입·진출 1차로씩 두고, 폭 0.40m씩 표시한다.

중앙 점유 박스는 x=2.5–3.5, y=0.6–1.6m다. 진입 정지선은 W의 x=2.25, E의 x=3.75, S의 y=1.85m에 각 진입 차로만 가로지르게 둔다. 진출 검지선은 해당 반대 차로의 x=2.20, x=3.80, y=1.90m다. 측정에 따라 넓힌다. 차체 뒤쪽까지 나갔는지 검지하고 정지 표식과 주행선의 색 또는 패턴을 구별한다. 단일 차량으로 회전 시 차체가 점유하는 폭, 정지거리, 시야 가림을 기록한 뒤 테이프 위치를 확정한다.

- 3대는 W1/E1/S1을 각 방향에 한 대씩 두고 정지·전환·출구를 확인한다. 첫 경로는 W→E, E→W, S→W다. 출발 전에 목적지와 분기 표식을 지정한다.
- 4대는 W1/E1/S1/S2로 남쪽 2대 대기열을 만든다. 앞차 전체가 출구를 넘을 때까지 뒤차는 기다린다.
- 6대는 2/2/2의 균등 배치와 1/2/3의 편중 배치를 번갈아 시험한다. 편중 배치에서는 해당 시험의 차량 ID→방향·목적지 등록표를 별도로 저장한다. 첫 트랙에서는 도착 차량을 회수하고 다음 반복의 위치와 출발 간격을 동일하게 재설정한다.

## SUMO에서 실차 입력으로

상부 카메라로 W/E/S 접근, 정지선, 내부, 출구 구역을 등록한다. 차량별 표식 ID를 사용하면 동일 차량의 정지시간과 출구 통과를 추적할 수 있다. 투입 지점에서 차량 투입 요청과 실제 진입을 따로 기록한다. [OpenCV ArUco 검출](https://docs.opencv.org/4.12.0/d5/dae/tutorial_aruco_detection.html)

| 방향별 입력 | 얻는 방법 |
|---|---|
| 접근 차량 수와 정지 큐 | 구역별 차량 ID, 속도 기준과 지속시간 |
| 평균 연속 정차 및 최장 대기 | 연속 정차 시간과 누적 정차/진입 대기 최대를 별도로 계산 |
| 진입 대기와 최근 30초 요청 | 투입 요청 원장과 접근 구역 유입의 차이, 요청 시간창 집계 |
| 내부 점유 | 상부 카메라와 진입·출구 이벤트 교차 확인 |
| 현재 현시·녹색 경과·전환 | 중앙 신호 제어기의 단조시각과 상태 |

25개 입력의 순서와 스케일은 [상태·행동·보상](../../docs/state_action_reward.md)과 체크포인트 옆 스키마에 있다. 미측정 값을 차량 0대로 해석하지 않는다. 실제 관측이 불완전하면 DQN으로 진입을 제어하지 않는다.

원래 SUMO는 250m 접근로, 5m 차량, 1초 시뮬레이션 스텝을 사용한다. 트랙에서 접근 속도, 제동 거리, 허가 후 출발 지연, 직진·회전 통과 시간을 재고 축소 SUMO의 길이·차량·차간격·시간 설정에 반영한다. 스텝을 줄이는 경우 환경과 보상 누적, 안전 타이머를 함께 바꾸고 테스트한다. 축소 환경에서 다시 학습·평가한 뒤 관측값의 범위를 실제 트랙과 비교한다.

## 비교 순서

한 대로 센서·정지·회전 → 세 대로 고정/규칙과 UDP → 네 대 편중에서 실차 관측 기반 DQN shadow → 축소 SUMO 보정·재학습 → 동일한 차량 투입 순서로 고정·규칙·DQN을 반복 비교한다. 차량 요청·진입·출구 시각과 정차 시간을 남기고 차량당 지연, 완료율, 최장 대기, 미진입, 상충 동시 허가, 통신 끊김 시 정지 결과를 각각 집계한다. 실제 트랙 검증은 현장 체크리스트의 결과와 함께 기록한다.
