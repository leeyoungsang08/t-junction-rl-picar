# 실차보다 많은 차량으로 학습·검증 (v16 → v18, 2026-11-16)

실차 PiCar는 6대라 혼잡 상황을 만들 수 없다. 시뮬레이션에서 차량 수와 맵 크기를 늘려 학습하고,
실제 코스 6대 성능을 잃지 않는지 함께 확인했다.

## 바꾼 것

| 항목 | 내용 | 실차에서 쓸 수 있나 |
|---|---|---|
| 큰 맵 (`map_builder.MAP_SCALES["large"]`) | 순환로·연결로 길이 2.5배 (8.65 × 5.75 m). 차로 폭·정지선·교차로 형상·차량·신호 규칙은 그대로. 수용 170대 | 시뮬레이션 전용 |
| 관측 picar_v3 | v2 + 진입로별 구간 차량 수 (`SegmentTracker.count`). v2의 `approach_n`은 정지선 앞 1.2 m만 봐서 3~4대에서 포화 | 예. 중앙서버가 REGISTER/IN/EXIT 이벤트로 이미 세는 값 (`real_bridge.seg_in`) |
| 학습 데이터 (`config/mixed_scenarios.yaml`) | 실제 코스 2~6대 + 큰 맵 8~50대, 수요 4종. `alternating`은 테스트 전용 | - |
| 보상 정규화 (v18, `reward.load_norm_cars: 6`) | 스텝 보상 ÷ max(1, 차량 수 / 6). 에피소드마다 상수이므로 에피소드 안의 최적 행동은 그대로 | - |

## 합격 기준 (학습 전에 정함)

1. 충돌·교차로 내 상충·정지선 위반이 모든 조건에서 0
2. 실제 코스 6대 평균 지연이 v15보다 5% 넘게 나빠지지 않을 것
3. 큰 맵 혼잡 상황에서 가장 좋은 규칙보다 평균 지연이 낮고, 대응 표본 95% 신뢰구간이 0 아래

## 과정 (한 번에 하나씩)

| 버전 | 바꾼 것 (직전 대비) | 실제 코스 6대 지연 (oldest_first 2.65 s) | 판단 |
|---|---|---|---|
| v15 | 기존 (실제 코스 2~5대만 학습) | 2.83 s | 기준선 |
| v16 | 학습 데이터만 혼합 | 4.04 s | 불합격 |
| v17 | v16 + picar_v3 관측 | 3.72 s | 불합격. 검증 seed로 체크포인트 40개를 다 봐도 최선 2.99 s → 모델 선택이 아니라 학습 문제 |
| **v18** | v17 + 보상 정규화 | **2.43 s** | 원인 확인: 혼잡 에피소드 보상 크기가 약 7배(−370 vs −55)라 학습을 끌고 감 |

v16·v17은 seed 42만 학습했고(seed 43은 원인 확인 후 중단), 예비 결과는 `runs/prelim_v16_v17/`에 있다.
이 예비 판정에 테스트 seed(3000~)를 썼기 때문에, 최종 판정은 처음 쓰는 seed(실제 코스 6000~, 큰 맵 8000~)로 다시 했다.

- 기준 1: 충돌·상충·위반 0 (전 조건 2,800 에피소드), 교착 0.
- 기준 2: 실제 코스 6대 v18 2.60 s vs v15 2.91 s (−11%) → 합격.
- 기준 3: 큰 맵 30·40·50대에서 합격 (평균 지연 −22%, −12%, −5%). 큰 맵 30대 처리량 +2.5%, 평균 대기열 2.7 → 2.2대.
- 혼잡할 때 DQN은 신호 전환이 적다(큰 맵 30대 36회 vs oldest_first 41회). 전환마다 생기는 황색·전적색 손실을 줄여 처리량을 늘린 것으로 보인다.

## 한계

- 한산한 큰 맵(10대)과 실제 코스 6~8대에서는 **최장 대기가 규칙보다 1.6~2.6 s 길다**. 평균은 같거나 낫지만 꼬리가 나쁘다.
- 혼잡 구간 성능은 v15(실제 코스만 학습)와 거의 같다. v15도 이미 혼잡으로 일반화되어 있었고, v18이 더한 것은 **실제 코스 4~6대와 한산한 큰 맵의 개선**이다.
- 큰 맵은 실차로 검증할 수 없다. 시뮬레이션상의 혼잡 대응 능력을 보이는 근거로만 쓴다.
- 학습 seed 2개. seed 43이 테스트에서 조금 더 좋지만, 검증 점수 기준(사전 규칙)으로 seed 42를 기본으로 쓴다.

## 재현

```bash
python -m picar_sim.train --seed 42 --out runs/picar_v18_mix_seg_norm --episodes 2000 --control-mode direct \
  --obs-schema picar_v3 --starvation-s 8 --starvation-weight 1.0 --switch-weight 0.1 --load-norm-cars 6 \
  --max-wait-guard 20 --scenarios picar_sim/config/mixed_scenarios.yaml --validation-every 50 --backend numpy
python -m picar_sim.stress_test --runs runs/picar_v15_obsage_tail/s8w1 runs/picar_v18_mix_seg_norm --map large \
  --cars 10 20 30 40 50 --biases uniform connector_heavy west_heavy alternating --seeds 8 --seed-base 8000 \
  --out runs/final_v18_large
```

Gazebo (실제 코스, 6대까지):
```bash
ros2 launch picar_gazebo course.launch.py cars:=3 \
  policy:=$PICAR_REPO/runs/picar_v18_mix_seg_norm/seed42/best_policy.npz mode:=active
```
